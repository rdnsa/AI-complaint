AI Complaint

Klasifikasi dan penentuan prioritas keluhan toilet berbasis LLM
UPI Kampus Tasikmalaya · ai-complaint.yvrtz.workers.dev

1. Ringkasan sistem

Mahasiswa memindai QR di pintu toilet, menulis keluhan dengan bahasa bebas, lalu pretrained LLM mengubahnya menjadi tiket kerja terstruktur — kategori, prioritas, ringkasan netral, dan rekomendasi tindakan. Tidak ada pelatihan model dan tidak ada dataset yang perlu dilabeli; kendali mutu dilakukan lewat rekayasa prompt dan validasi keluaran.

QR per lantai  →  pilih jenis WC  →  tulis keluhan + foto  →  LLM
                                                                ↓
                          dashboard petugas  +  cron 17.00 WIB → ringkasan harian

3. Arsitektur

Backend disusun berlapis dengan arah ketergantungan hanya ke dalam. Aturan tiap lapisan diperiksa dan tidak ada yang dilanggar.

routes/  →  services/  →  repositories/  →  D1
                ↓
           adapters/            domain/
LapisanTanggung jawabAturan yang dipatuhi
domain/Kosakata dan aturan masalahTidak mengimpor apa pun — tanpa Hono, D1, R2
repositories/Seluruh pernyataan SQLTahu basis data, tidak tahu HTTP
services/Use case dan aturan bisnisTidak menyebut Hono sama sekali
adapters/LLM, R2, hash sandi, sesi, waktuMembungkus dunia luar
routes/Parse, validasi, delegasi, formatNol SQL, nol aturan bisnis
Konsekuensi yang dapat diuji: seluruh 38 pernyataan SQL berada di repositories/. Berpindah dari D1 ke Postgres berarti menulis ulang satu direktori, bukan seluruh berkas route. Aturan “laporan hanya boleh ditutup bila ada bukti” tinggal di lapisan domain, sehingga setiap pemanggil memutuskan dengan cara yang sama.

5. Alur analisis LLM

Tiga hal menjaga keluaran model tetap dapat dipercaya:

Prompt berbasis aturan, bukan contoh acak

Prompt sistem mendefinisikan enam kategori dan tiga tingkat prioritas dengan kriteria eksplisit berbasis risiko keselamatan — bukan berbasis kata kunci. Ditambah tiga contoh few-shot untuk mengunci gaya bahasa dan penerapan aturannya.

Validasi berlapis

respons JSON → Zod schema → coerceAnalisis() → enum basis data

Kategori di luar daftar dibuang; prioritas tak dikenal jatuh ke sedang. Model tidak pernah bisa menuliskan nilai yang tidak dikenal basis data.

Asinkron dan tahan gagal

Analisis dijalankan lewat ctx.waitUntil() setelah respons dikirim, sehingga pelapor menerima konfirmasi seketika. Kegagalan ditandai ai_status='gagal' beserta pesan errornya; laporan tetap tampil di dashboard dan dapat dianalisis ulang. Latensi tiap panggilan disimpan di kolom ai_ms sebagai data kuantitatif.

7. Empat keputusan rancangan yang berbiaya

Jejak audit sengaja tanpa foreign key

Tabel aktivitas tidak menunjuk reports dengan foreign key. Alasannya justru laporan yang dihapus-lah yang paling perlu terlacak. Saat penghapusan, seluruh isi laporan disalin ke kolom rincian sebelum barisnya hilang, lengkap dengan pelaku dan waktunya. Foreign key akan memaksa baris audit ikut terhapus — kebalikan dari tujuannya.

Penyelesaian menuntut bukti, ditolak di server

Baik foto keadaan dari pelapor maupun foto bukti dari petugas divalidasi di sisi server, bukan sekadar disembunyikan di antarmuka. Status selesai tanpa foto_selesai_key dijawab 400.

Foto tidak melewati domain pihak ketiga

Endpoint GET /api/uploads/<key> membaca objek langsung dari binding R2. Selain menghilangkan kebutuhan membuka bucket ke publik, ini menghindari domain pub-*.r2.dev yang DNS-nya dibajak sebagian ISP di Indonesia — terverifikasi saat pengembangan: resolver lokal mengembalikan alamat non-Cloudflare dan koneksi TLS gagal, sedangkan lewat 1.1.1.1 hostname yang sama benar mengarah ke Cloudflare.

Warna grafik dihitung, bukan dikira-kira

Palet deret dan palet prioritas lolos pemeriksaan rentang terang, ambang chroma, keterpisahan bagi buta warna (deutan/protan/tritan), dan kontras terhadap latar. Ramp sekuensial untuk heatmap diverifikasi monoton dalam luminansi (0,933 → 0,164).

9. Penyebaran

npx wrangler secret put LLM_API_KEY
npx wrangler secret put AUTH_SECRET

npm run db:remote        # migrasi D1 produksi
npm run db:seed:remote   # daftar toilet
npm run deploy

Cloudflare Workers Builds cukup disetel dengan perintah deploy npx wrangler deploy; frontend dibangun sendiri lewat build.command yang juga memasang dependensi pada checkout bersih. Cron 0 10 * * * (17.00 WIB) memicu penyusunan ringkasan harian.
